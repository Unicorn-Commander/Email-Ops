# Release notes (pending): 2026-11-12

Plain-language notes for Email-Ops changes merged to main, PR #95 through #107.
Three changes are user or operator visible (#102, #100 and #107); the rest are
tests and docs that harden or document existing behavior.

## Highlights

- **#102 (fix, no flag, always on):** Approving the same agent-inbox item twice
  in a row, or from two tabs at once, used to send the email twice. Approval now
  claims the item atomically, so exactly one approve results in exactly one send.
- **#100 (feature, flag-gated):** You can now Disconnect an external IMAP
  mailbox from the Mail page. Email-Ops wipes the stored app password and marks
  the mailbox inactive; nothing is deleted at the provider. Only the mailbox
  owner can do it, and only while external IMAP is on for the workspace
  (flags: `EXTERNAL_IMAP_ENABLED` plus the `EXTERNAL_IMAP_WORKSPACE_IDS`
  allowlist).
- **#107 (fix, no flag, always on):** NOTICE items in the agent inbox used to
  open nothing when you clicked them, because the thread id was read from the
  wrong payload field. They now open the flagged message's thread, and the
  card shows that message inline (sender, subject, received time and body),
  so you can read what was flagged without leaving the inbox.

## Every PR

- **#95 (docs, no flag):** The mailbox help pages (connect your mailbox,
  connect another provider, disconnect a mailbox) now link to each other.
- **#96 (tests, no flag):** New tests prove the external IMAP connector only
  works for workspaces on the per-workspace allowlist.
- **#97 (docs, no flag):** New operator guide for the external IMAP allowlist,
  covering `EXTERNAL_IMAP_ENABLED`, `EXTERNAL_IMAP_WORKSPACE_IDS` and
  `EXTERNAL_IMAP_SEND_ENABLED`.
- **#98 (tests, no flag):** New tests prove approving an agent-inbox item sends
  the email exactly once.
- **#99 (tests, no flag):** New tests prove `compose_email` is idempotent on
  `external_ref`, so a retried agent call does not create duplicate drafts.
- **#100 (feature, flag-gated):** Disconnect button for external IMAP
  mailboxes, wiping the stored credential (see Highlights).
- **#101 (tests, no flag):** New tests prove suppressed recipients are never
  sent mail, in every send path.
- **#102 (fix, no flag):** Concurrent approvals of one agent-inbox item now
  send the email once, not twice (see Highlights).
- **#103 (tests, no flag):** New tests prove mailbox Disconnect really wipes
  the stored credential.
- **#104 (docs, no flag):** New operator doc describing the agent-inbox item
  lifecycle (pending, approved, rejected) as the code implements it.
- **#105 (tests, no flag):** New end-to-end test drives the external IMAP
  connector against the fake IMAP server fixture, connect through disconnect:
  a disabled flag or a wrong password is refused, the stored credential is
  encrypted, the inbox lists the fixture's three threads, and Disconnect
  wipes the credential. The test also proves no real network or DNS call is
  made and no password appears in responses, logs or wire commands.
- **#106 (fix, no flag):** Disconnecting a mailbox now writes one audit entry
  in each workspace where a mailbox was deactivated, recording the actor,
  provider and outcome, and clears the mailbox inbound sync cursor, so
  reconnecting starts with a clean first sync.
- **#107 (fix, no flag):** Agent-inbox NOTICE items open their thread and
  show the flagged message inline (see Highlights).

## How to verify after release

Sign in at https://email-ops.unicorncommander.ai and check:

1. **#102:** Open an agent-inbox item in the inbox, approve it, and confirm
   exactly one message appears in Sent and the item shows as approved, with
   no duplicate send.
2. **#100:** With external IMAP enabled for your workspace, open the Mail page
   and confirm a Disconnect action appears next to your own external IMAP
   mailbox; use it on a test mailbox and confirm the mailbox shows as
   disconnected and no longer syncs.
3. **#106:** Disconnect one of your mailboxes on a test workspace, then check
   that workspace's audit events (agent action events) for one mailbox-updated
   entry with the actor, provider and outcome, and no token or password in
   the detail; confirm the mailbox row's inbound sync cursor is now empty.
4. **#107:** Open the agent inbox, find a NOTICE item and click the card: the
   review panel should open (it used to open nothing), the card should show
   the flagged message inline with sender, subject and body, and "Open
   thread" should jump to that thread in the Mail page.
