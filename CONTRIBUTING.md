# Contributing

Thank you for helping improve Email-Ops. Keep changes focused on the problem they solve and preserve the workspace, authorization, and human-approval boundaries.

Before opening a pull request:

- Explain the user-facing or operational behavior that changed.
- Add or update focused tests for backend behavior and authorization changes.
- Run the relevant backend, frontend, or Cleaner Engine checks listed in the [README](README.md#development).
- Do not commit credentials, private mail content, generated dependencies, or local environment files.

Pull requests should include enough context for a reviewer to reproduce the behavior and should call out any configuration or migration work explicitly.
